# Agent Owner's Manual — [agent name]

One per production agent. Fifteen fields answered precisely beats forty answered
vaguely.

| # | Field | Value |
|---|---|---|
| 01 | Agent name | |
| 02 | Purpose — why we have it, in one sentence a non-engineer accepts | |
| 03 | Business owner — a named person, not a team | |
| 04 | Technical owner — a named person who can change its behaviour | |
| 05 | Trigger — what starts it | |
| 06 | Users — who it acts for | |
| 07 | Data sources | |
| 08 | Connected systems | |
| 09 | What it can read (technical capability) | |
| 10 | What it can change (technical capability) | |
| 11 | Autonomous actions (mandate) | |
| 12 | Approval-required actions (mandate) | |
| 13 | Prohibited actions (mandate) | |
| 14 | Escalation path — named recipient, time limit, and what happens if nobody answers | |
| 15 | Shutdown procedure — including who may run it and how it was last tested | |

**Check before signing off:** is field 10 broader than 11 and 12 combined? That
difference is the attack surface. Record it in the risk register, and close it
in the credential rather than in the instruction.
